# 第一次使用银河麒麟：从 Windows 迁移到国产 Linux 桌面的入门指南

第一次打开银河麒麟，很多人会下意识地寻找熟悉的 Windows 操作入口：软件应该去哪里下载？文件存在哪个盘？为什么有些操作需要输入密码？终端里的命令是不是都必须记住？

其实，日常办公并不依赖大量命令。开始菜单、任务栏、文件管理器和系统设置仍然是我们熟悉的图形界面，真正需要改变的是对文件目录、权限和软件安装方式的理解。

这篇文章根据我此前编写的《银河麒麟系统使用指导手册》重新整理。公开版删除了单位专用软件、内部共享地址和特定网络环境，保留新手入门所需的背景知识、操作解释、AI 助手使用案例、命令速查和常见问题。它不是一张“命令清单”，而是一份可以按章节阅读的完整入门指南。

> 适用对象：第一次接触银河麒麟桌面系统的办公用户和初学者。
> 主要环境：银河麒麟桌面 V10（SP1/SP2/SP3/SP4），UKUI 桌面。不同版本的菜单名称、默认软件和命令输出可能略有差异。
> 阅读建议：急着上手可先读第一、二、六、七章；想理解 Linux 与 Windows、macOS 的关系，再读第三至五章。

## 一、快速入门：先认识这台电脑

### 1.1 银河麒麟到底是什么

银河麒麟（Kylin）是麒麟软件推出的国产操作系统。我们日常接触的桌面版通常采用 UKUI 桌面，提供开始菜单、任务栏、系统托盘、文件管理器等常见组件。

对普通用户来说，文档处理、网页浏览、即时通信、音视频播放等任务，仍然主要通过图形界面完成。Linux 并不意味着每天都要对着黑色窗口输入命令。

可以先用一句话建立基本认识：

> 银河麒麟桌面版是一套以 Linux 为内核、面向国产软硬件生态进行适配的桌面操作系统；它既有图形界面，也保留了 Linux 完整的命令行和开发能力。

需要特别注意，**银河麒麟桌面版与服务器版的软件管理方式可能不同**。桌面 V10 常见 `apt` 和 `.deb` 软件包；服务器环境也可能使用 `dnf` 或 `yum`。开始操作前，应先确认自己的系统版本，不要把不同发行版的教程混在一起。

### 1.2 它比 Windows 更难用吗

“不同”不等于“更难”。Windows、macOS 和 Linux 都有各自的优势：

| 维度 | Windows | macOS | 银河麒麟 / Linux |
|---|---|---|---|
| 日常办公 | 软件覆盖广，用户基础大 | 与 Apple 生态结合紧密 | 常用办公任务可通过原生软件完成 |
| 开发环境 | 可借助 WSL 等获得 Linux 环境 | 自带 Unix-like 环境 | 原生 Linux 工具链 |
| 界面与硬件 | 厂商和机型丰富 | 软硬件高度整合 | 桌面和硬件选择较多，适配情况需逐机确认 |
| 软件安装 | 安装包、商店、包管理器 | App Store、安装包、Homebrew | 应用商店、apt、deb、源码等 |
| 自主配置 | 图形设置为主 | 系统边界明确 | 配置自由度较高，也要求更谨慎 |

迁移初期的不适应，往往来自操作习惯而不是系统本身。例如找不到盘符、不知道软件包名称、遇到权限提示，只要理解背后的规则，就能逐渐顺手。

### 1.3 Linux 与 AI 工具链的关系

Linux 在 AI 和服务器领域应用广泛。PyTorch、TensorFlow、Hugging Face、vLLM，以及 Docker、Kubernetes 等云原生工具，都把 Linux 作为重要运行环境。很多国产 CPU、GPU、NPU 和加速框架也优先提供 Linux 驱动与开发套件。

这并不意味着普通办公用户必须学习模型训练，而是说：当我们开始接触 AI 编程助手、自动化脚本、本地知识库和智能体时，Linux 的基础知识会越来越有用。

学习几个命令，不是为了“显得专业”，而是为了看懂电脑正在做什么。

### 1.4 怎么打开终端

本指南中的命令都在终端中执行。打开终端通常有三种方法。

**方法一：快捷键**

按 `Ctrl + Alt + T`，桌面会弹出终端窗口。

**方法二：开始菜单**

1. 点击桌面左下角的开始按钮；
2. 搜索“终端”或“Terminal”；
3. 点击对应应用。

**方法三：文件管理器**

在文件管理器的目录空白处右键，选择“在终端中打开”。这种方式会直接以当前目录作为终端工作目录。

常见提示符类似：

```text
username@computer:~$
```

- `username`：当前用户名；
- `computer`：主机名；
- `~`：当前用户的家目录；
- `$`：普通用户提示符。

我们只需要在 `$` 后输入命令，不要把提示符本身一起输入。

### 1.5 新手最常遇到的终端问题

| 问题 | 处理方法 |
|---|---|
| 终端里打不了字 | 先点击终端窗口，确认它获得焦点 |
| 命令输错了 | 未执行时可修改；需要中断当前操作时按 `Ctrl+C` |
| 无法复制粘贴 | 多数终端使用 `Ctrl+Shift+C`、`Ctrl+Shift+V` |
| 路径太长 | 输入前几个字符后按 `Tab` 自动补全 |
| 想重复上一条命令 | 按上方向键调出历史命令 |
| 命令执行后没有输出 | Linux 中“没有消息”经常表示成功，不能一概视为故障 |

命令行中的路径使用 `/`，例如 `/home/user/Documents`；Windows 常见的是 `\`，例如 `C:\Users\user\Documents`。

## 二、用 AI 助手降低 Linux 使用门槛

### 2.1 AI 助手能帮我们做什么

过去的命令行学习依赖查书、搜索和反复试错。现在，AI 编程助手或终端智能体可以承担一部分解释和操作工作：

| 自然语言需求 | AI 可以协助完成的工作 |
|---|---|
| 帮我看看电脑配置 | 调用系统信息命令并整理结果 |
| 帮我安装一个软件 | 判断包名、系统架构和安装方式 |
| Wi-Fi 突然连不上了 | 检查网络接口、服务状态和日志 |
| 找出占空间的大文件 | 扫描目录并汇总文件大小 |
| 解释一条命令 | 拆解参数，指出作用和风险 |
| 写一个定时备份脚本 | 生成脚本、说明定时任务配置方法 |
| 分析一段报错 | 结合错误信息给出排查顺序 |

它与传统问答工具的区别在于：部分终端智能体不仅能回答，还能在获得授权后执行命令、修改文件和安装软件。

因此，AI 可以降低入门门槛，但也带来了新的责任：**它能执行，不代表它给出的每一步都应该执行。**

### 2.2 一个具体示例：Qoder CLI

原手册曾以 Qoder CLI 为例演示终端 AI 助手。公开版保留这个示例，用于说明安装和交互方法，不构成对某一产品的唯一推荐。

原手册记录的一键安装方式为：

```bash
curl -fsSL https://qoder.com.cn/install | bash
```

安装后，原手册使用的验证和登录命令为：

```bash
qoderclicn --version
qoderclicn login
```

进入交互模式：

```bash
qoderclicn
```

然后可以用自然语言提出一个只读请求：

```text
你好，帮我看看本机的 IP 地址，并解释每块网卡的用途。
```

> 产品命令、登录方式、免费额度和支持平台会随版本变化。实际操作前，应以 Qoder 官方文档为准。执行通过网络下载并直接运行的安装脚本前，也应先确认域名和来源。

### 2.3 十个适合新手的 AI 交互案例

以下案例不限定某一款 AI 工具。重点是学习如何提出清晰需求，以及如何让 AI 先解释、再执行。

#### 案例一：查看电脑配置

```text
请查看这台电脑的 CPU、内存、磁盘、系统版本和处理器架构。
只执行查询命令，不修改任何配置，最后整理成表格。
```

可能涉及：

```bash
lscpu
free -h
df -h
uname -a
```

#### 案例二：安装文本编辑器

```text
请帮我安装 Vim。先确认当前系统是否使用 apt，再给出准备执行的命令。
安装完成后告诉我如何启动和退出。
```

这比一句“帮我装软件”更明确，因为限定了先确认包管理器。

#### 案例三：排查 Wi-Fi

```text
我的 Wi-Fi 突然无法连接。请先检查网络接口、NetworkManager
服务状态和近期错误日志。不要重启网络，不要修改配置，
先给我一份诊断结果。
```

排查网络时，先收集信息比直接重启服务更容易保留故障现场。

#### 案例四：寻找大文件

```text
请找出我的家目录中大于 1GB 的文件，按大小排序。
只查询，不删除。
```

“只查询，不删除”是非常有用的边界条件。

#### 案例五：分析磁盘空间

```text
我的磁盘空间不足。请先分析各分区和主要目录的空间占用，
列出可以清理的候选项，并分别说明风险。不要直接清理。
```

AI 可以给出 `apt` 缓存、旧日志、临时文件等建议，但是否删除应由用户决定。

#### 案例六：生成备份脚本

```text
请写一个 Bash 脚本，把 ~/Documents 备份到指定目录，
保留最近 7 次备份。脚本需要包含路径检查、错误处理和日志。
先解释方案，不要马上创建定时任务。
```

定时备份必须确认目标磁盘容量、备份目录和恢复方法。备份脚本生成后，还应进行一次恢复测试。

#### 案例七：解释危险命令

```text
请逐段解释下面命令的作用和潜在风险，不要执行：
sudo find / -name "*.log" -mtime +30 -delete
```

这条命令会从根目录搜索符合条件的日志并删除。看到 `-delete`、`rm -rf`、磁盘格式化和分区操作时，应先停下来确认。

#### 案例八：转换文本编码

```text
请把当前目录的 GBK 编码 TXT 文件转换为 UTF-8。
先备份原文件，只处理明确匹配的文件，并抽样验证转换结果。
```

批量转换前保留原文件，能避免编码判断错误导致内容损坏。

#### 案例九：解释软件安装报错

```text
请解释这个错误：E: Unable to locate package xxx。
请按“包名错误、索引未更新、仓库未收录、架构不支持”的顺序排查。
```

清晰的排查顺序，比让 AI“直接修好”更可靠。

#### 案例十：诊断系统卡顿

```text
请检查 CPU、内存、磁盘空间和近期错误日志，分析系统卡顿原因。
不要结束进程，不要清理文件，先输出证据和建议。
```

可能涉及 `top`、`free -h`、`df -h`、`journalctl` 等命令。

### 2.4 给 AI 下指令的四个原则

1. **先只读，后修改**：先收集信息，再决定操作。
2. **明确边界**：写清“不删除、不重启、不修改配置”。
3. **要求解释**：让 AI 说明命令作用、适用版本和风险。
4. **保留回退**：重要操作前备份，操作后验证结果。

涉及删除文件、修改权限、更换软件源、关闭安全组件等操作时，不能只因为命令由 AI 生成就直接执行。AI 更适合成为解释器和辅助排障工具，最终执行决定仍应由使用者作出。

## 三、为什么使用银河麒麟

### 3.1 从一台新机器说起

第一次开机看到陌生的桌面，找不到熟悉的软件，难免会有心理落差。但计算机仍然是“硬件 + 操作系统 + 应用软件”的结构。换操作系统更像换一套房子的布局：基本功能仍在，只是需要重新认路。

银河麒麟的意义，也不只是提供一个 Windows 的替代界面。它处在国产芯片、固件、数据库、中间件和应用软件之间，是软硬件生态的重要连接层。

### 3.2 信创替换不只是“换一个系统”

信息技术应用创新涉及从底层硬件到上层应用的整体适配。操作系统迁移通常只是其中一环，还需要考虑：

- CPU 架构与指令集；
- 显卡、打印机、指纹仪等外设驱动；
- 办公软件与文档格式兼容；
- 业务系统插件和浏览器适配；
- 数据迁移与备份；
- 安全策略、运维体系和用户培训。

因此，在实际工作中，“系统能否安装”只是第一步，“软件能否协同、数据能否延续、问题能否维护”同样重要。

### 3.3 国产 Linux 桌面的优势与现实边界

国产 Linux 桌面的优势包括：适配国产处理器和整机、支持本地安全策略、拥有开放的 Linux 工具链、便于自动化和集中运维。

同时也应承认现实边界：部分行业软件仍只提供 Windows 版本；个别外设驱动依赖厂商；不同系统版本和硬件组合可能存在差异。遇到兼容问题时，应优先寻找原生替代、网页版或厂商适配方案，而不是简单认定“Linux 都能装”或“国产系统不能用”。

客观看待优势和限制，比单纯争论哪个系统更好更有意义。

## 四、三大操作系统的“家谱”

### 4.1 Unix、Linux 与 macOS

Unix 诞生于 1969 年，对后来的操作系统设计产生了深远影响。macOS 的底层包含 BSD 等 Unix 技术脉络；Linux 内核则由 Linus Torvalds 于 1991 年开始开发，并不是 Unix 代码的简单复制。

为了便于理解，可以把它们比作“同一技术文化中的不同分支”：

```text
Unix 的技术思想与接口标准
├── BSD 等分支 ── NeXTSTEP ── macOS 的部分底层技术
└── Unix-like 设计影响 ── Linux 内核 + GNU 等工具 ── 各种 Linux 发行版

Windows NT 则形成了另一条独立的技术路线。
```

这里的“家谱”是帮助理解的概念模型，不宜把“嫡系”“养子”等比喻当作严格的代码来源判断。

### 4.2 为什么 macOS 和 Linux 的命令很相似

两者都属于 Unix-like 使用环境，提供许多名称和用途相近的工具，例如：

```bash
ls
cd
cp
mv
grep
ssh
curl
```

但“相似”不等于“完全相同”。同一个命令在不同系统上的参数可能不同，脚本也不能未经验证直接照搬。

| 差异 | macOS | Linux |
|---|---|---|
| 常见软件安装 | Homebrew、App Store、安装包 | apt、dnf、安装包等 |
| 服务管理 | launchd / launchctl | 常见 systemd / systemctl |
| 默认工具实现 | 部分来自 BSD | 常见 GNU 工具 |
| 文件系统大小写 | 默认配置通常不敏感 | 通常区分大小写 |

所以，“我在 Mac 上用过 `ls`”可以帮助理解 Linux，但不能由此推断 `apt`、系统服务命令或所有脚本都能通用。

### 4.3 POSIX、GNU、BSD 是什么

| 缩写 | 含义 | 可以怎样理解 |
|---|---|---|
| POSIX | Portable Operating System Interface | 一类操作系统接口标准，让不同系统具有相似的基础行为 |
| GNU | GNU's Not Unix | 自由软件项目，为许多 Linux 系统提供编译器、Shell 和基础工具 |
| BSD | Berkeley Software Distribution | Unix 的重要分支，对网络、系统工具和后续系统影响深远 |

不需要背诵这些名词。只要理解：命令相似来自共同的技术标准和历史积累，而不是因为所有系统都使用同一套代码。

### 4.4 Windows 为什么走另一条路也很好用

Windows 的成功并不取决于是否具有 Unix“血统”，而在于图形界面、硬件覆盖、商业软件生态、企业管理和长期兼容性。

Office、行业软件、游戏和大量外设让 Windows 形成了强大的生态。Linux 的优势则更多体现在开放工具链、服务器、开发环境和可定制性。选择系统时，应看具体任务和生态，而不是只看技术历史。

## 五、用“房子”理解 Windows、macOS 与 Linux

如果把操作系统比作房子，可以这样理解：

| 维度 | macOS：整体设计住宅 | Windows：标准化精装房 | Linux：可自主改造的房子 |
|---|---|---|---|
| 硬件与系统 | 整合程度高 | 机型和厂商丰富 | 硬件和发行版选择多 |
| 界面 | 风格统一 | 统一中有一定定制空间 | 桌面环境选择较多 |
| 软件来源 | 商店、官方安装包等 | 商店、安装包、管理工具 | 仓库、安装包、源码等 |
| 系统修改 | 边界相对明确 | 图形设置为主 | 自由度高，误操作风险也高 |
| 适用特点 | Apple 生态与一体化体验 | 通用办公与商业软件生态 | 开发、服务器、自主配置 |

“可自主改造”并不等于每一行代码都由使用者掌握，也不代表所有组件都开放。它更多意味着系统提供较大的配置和组合空间。

对新手来说，这个比喻最重要的提醒是：**自由度越高，越需要理解操作后果。**Windows 中不熟悉的系统目录不应随便改，Linux 中同样如此。

## 六、Linux 与 Windows 的使用习惯差异

### 6.1 思维方式对照

| Windows 习惯 | 银河麒麟 / Linux 对应方式 | 需要建立的认知 |
|---|---|---|
| 从开始菜单进入应用 | UKUI 开始菜单、任务栏、搜索 | 图形操作仍然普遍存在 |
| C 盘、D 盘、E 盘 | 以 `/` 为根的目录树，分区挂载到目录 | 盘符不是唯一组织方式 |
| 双击 `.exe` | 应用商店、apt、deb 等 | 软件格式和依赖机制不同 |
| Program Files | `/usr`、`/opt` 等 | 用户通常不需要手工选择安装目录 |
| Administrator | 管理员授权、`sudo` | 临时提权，避免长期高权限运行 |
| `ipconfig` | `ip addr` | 命令名称不同，目标相同 |
| `dir` | `ls` | 都是列出目录内容 |
| 文件名大小写通常不敏感 | 通常严格区分大小写 | `README.md` 与 `readme.md` 可以是两个文件 |

### 6.2 文件系统：一棵以根目录开始的树

Linux 使用一棵以 `/` 为起点的目录树。硬盘、U 盘和其他分区会挂载到这棵树中的某个位置，而不是都表现为独立盘符。

```text
/
├── home/                 用户家目录
│   └── username/
│       ├── Documents/    文档
│       └── Downloads/    下载
├── usr/                  系统程序与共享资源
│   ├── bin/              常见命令
│   └── local/            本地安装的软件资源
├── etc/                  系统和服务配置
├── var/                  日志、缓存等变化数据
│   └── log/              系统日志
├── tmp/                  临时文件
├── opt/                  部分第三方应用
├── dev/                  设备文件
└── boot/                 内核与启动文件
```

常见目录说明：

| 目录 | 主要用途 | 新手注意事项 |
|---|---|---|
| `/home/用户名` | 个人文档、下载和用户配置 | 最重要的个人工作区域 |
| `/etc` | 系统配置 | 修改前应备份并了解用途 |
| `/usr` | 程序与共享资源 | 不要当作个人文件目录 |
| `/var` | 日志、缓存等 | 不要为释放空间随意清空 |
| `/opt` | 第三方应用 | 不同软件布局可能不同 |
| `/tmp` | 临时文件 | 不适合长期保存重要资料 |
| `/dev` | 设备文件 | 不应直接修改陌生设备节点 |
| `/boot` | 启动文件 | 与系统引导相关，谨慎操作 |

在终端中，`~` 代表当前用户的家目录。例如：

```bash
cd ~/Documents
```

等同于进入当前用户的 Documents 目录，不需要把真实用户名写死。

### 6.3 路径、大小写和扩展名

Linux 路径用 `/` 分隔：

```text
/home/user/Documents/report.txt
```

路径通常区分大小写：

```text
Report.txt
report.txt
```

这可能是两个不同文件。复制教程中的路径时，应注意大小写。

Linux 也使用 `.txt`、`.deb`、`.sh` 等扩展名，但系统判断文件类型并不完全依赖扩展名。脚本能否执行还与权限和解释器有关。

### 6.4 权限意识：sudo 是临时授权

Linux 对系统级修改有明确的权限边界。安装软件、修改系统配置等操作，经常需要在命令前加 `sudo`，并输入当前用户密码。

```bash
sudo apt update
```

`sudo` 的意义是让这条命令临时获得管理员权限，而不是让当前会话一直处于管理员状态。

可以用“临时借钥匙”理解它：平时使用普通权限，只有确有必要时才打开系统区域的门。

以下做法应谨慎：

- 为了省去权限提示，长期使用 root 桌面会话；
- 对不认识的目录递归执行 `chmod -R 777`；
- 直接复制来历不明的 `sudo` 命令；
- 把密码写进公开脚本或聊天内容。

遇到权限不足时，先确认文件位置、所有者和操作目的，不要简单理解为“权限越大越好”。

### 6.5 软件安装的几种方式

#### 方式一：应用商店

最适合普通用户。软件来源、架构和安装过程由系统统一管理，通常不需要关心命令。

#### 方式二：apt 软件仓库

适用于使用 `apt` 的桌面环境：

```bash
sudo apt update
apt search 关键词
sudo apt install 软件包名
sudo apt remove 软件包名
```

`apt update` 更新的是软件包索引，并不等于把系统里所有软件都升级。

#### 方式三：厂商提供的 deb 安装包

从软件官方网站下载与系统版本、CPU 架构匹配的 `.deb` 包。可以使用图形安装器，也可以在确认文件后使用命令安装。

```bash
sudo dpkg -i 软件包.deb
```

如果出现依赖问题，不要立刻反复强制安装。先阅读错误信息，确认系统版本和依赖来源，再选择修复方式。

#### 方式四：源码编译

主要面向开发者：

```bash
tar -xzf xxx.tar.gz
cd xxx
./configure
make
sudo make install
```

并非所有项目都使用这一流程。现代项目可能采用 CMake、Meson 或其他构建系统，应阅读项目文档。普通办公用户通常没有必要从源码编译常用软件。

### 6.6 ARM64 与 x86_64 不要混淆

国产笔记本可能采用 ARM64、x86_64 或其他架构。下载软件前可以查看：

```bash
uname -m
```

常见输出包括：

- `x86_64`：常见 Intel / AMD 64 位环境；
- `aarch64`：64 位 ARM 环境，软件下载页通常标为 ARM64。

为 x86_64 编译的安装包通常不能直接安装在 ARM64 系统上。看到“Linux 版”还不够，还要确认架构和发行版。

### 6.7 迁移第一周容易踩的坑

| 现象 | 可能原因 | 建议 |
|---|---|---|
| U 盘插入后没弹窗 | 已自动挂载但没有提示 | 看文件管理器侧边栏 |
| 软件安装后没有桌面图标 | 未创建快捷方式 | 从开始菜单搜索，或查命令名 |
| 修改配置后不生效 | 服务未重载或配置写错位置 | 先核对文档和服务状态 |
| `ipconfig` 不存在 | 是 Windows 命令 | 使用 `ip addr` |
| `dir` 不熟悉 | Linux 常用 `ls` | 用 `ls -lh` 查看详细信息 |
| 文件名找不到 | 大小写或路径不同 | 用 `Tab` 补全，避免手敲错误 |
| 提示 Permission denied | 当前用户权限不足 | 先确认是否应修改该系统文件 |
| 下载的 deb 无法安装 | 系统版本或架构不匹配 | 检查 `uname -m` 和软件要求 |
| 图形界面找不到某项设置 | 不同版本菜单不同 | 查当前版本文档，不照搬旧教程 |

## 七、常用命令速查

这一章用于需要时查阅，不要求一次背完。命令中的尖括号表示需要替换的内容，实际输入时不要保留尖括号。

### 7.1 文件和目录操作

| 命令 | 说明 | Windows 中的近似操作 |
|---|---|---|
| `pwd` | 显示当前目录 | 查看地址栏 |
| `ls` | 列出目录内容 | `dir` |
| `ls -lh` | 详细列表，易读大小 | 详细信息视图 |
| `ls -la` | 包含隐藏文件 | 显示隐藏项目 |
| `cd 目录` | 切换目录 | 进入文件夹 |
| `cd ..` | 返回上一级 | 向上 |
| `mkdir 名称` | 新建目录 | 新建文件夹 |
| `cp a.txt b.txt` | 复制文件 | 复制粘贴 |
| `cp -r dir1 dir2` | 递归复制目录 | 复制文件夹 |
| `mv old new` | 移动或重命名 | 移动、重命名 |
| `cat file.txt` | 输出短文本内容 | 查看文本 |
| `less file.txt` | 分页查看文本 | 分页阅读 |
| `find 目录 -name 名称` | 按名称查找 | 文件搜索 |

删除命令需要格外谨慎：

```bash
rm file.txt
```

`rm` 删除通常不等于移入桌面回收站。执行 `rm -r`、`rm -rf` 或包含通配符的命令前，应再次确认路径，并确保重要资料已有备份。

### 7.2 系统信息

| 命令 | 用途 |
|---|---|
| `whoami` | 查看当前用户名 |
| `hostname` | 查看主机名 |
| `hostnamectl` | 查看主机和系统信息 |
| `uname -a` | 查看内核等信息 |
| `uname -m` | 查看处理器架构 |
| `uptime` | 查看运行时间和负载 |
| `lscpu` | 查看 CPU 信息 |
| `free -h` | 查看内存 |
| `df -h` | 查看文件系统空间 |
| `top` | 动态查看进程与资源占用 |

在 `top` 中按 `q` 退出。

### 7.3 软件管理

以下适用于使用 `apt` 的环境：

| 命令 | 说明 |
|---|---|
| `sudo apt update` | 更新软件包索引 |
| `apt search 关键词` | 搜索软件 |
| `apt show 包名` | 查看软件包信息 |
| `sudo apt install 包名` | 安装软件 |
| `sudo apt remove 包名` | 移除软件包 |
| `sudo apt upgrade` | 升级可升级的软件包 |

升级系统组件前，应关注单位运维要求和重要软件兼容性，不要在关键工作任务前盲目进行大规模升级。

### 7.4 服务管理

| 命令 | 说明 |
|---|---|
| `systemctl status 服务名` | 查看状态 |
| `sudo systemctl start 服务名` | 启动服务 |
| `sudo systemctl stop 服务名` | 停止服务 |
| `sudo systemctl restart 服务名` | 重启服务 |
| `sudo systemctl reload 服务名` | 重载配置 |
| `sudo systemctl enable 服务名` | 设置开机启动 |
| `sudo systemctl disable 服务名` | 取消开机启动 |

不要随意停止不认识的服务。排障时应先使用 `status` 和日志确认影响范围。

### 7.5 权限管理

| 命令 | 说明 |
|---|---|
| `sudo 命令` | 临时以管理员权限执行 |
| `ls -l 文件` | 查看权限与所有者 |
| `chmod +x script.sh` | 为脚本添加执行权限 |
| `chown 用户:组 文件` | 修改所有者，通常需要合适权限 |

不要对系统目录递归执行 `chmod 777` 或随意改变所有者，这可能破坏应用和系统安全机制。

### 7.6 网络相关

| 命令 | 说明 |
|---|---|
| `ip addr` | 查看接口与 IP 地址 |
| `ip route` | 查看路由 |
| `ping -c 4 地址` | 发送四次连通性测试 |
| `curl -I 网址` | 查看 HTTP 响应头 |
| `wget 网址` | 下载文件 |
| `ssh 用户@主机` | 远程登录 |
| `scp 文件 用户@主机:路径` | 远程复制 |

IP 能连通并不代表域名解析或应用服务一定正常。排查网络时，还需要继续检查 DNS、代理和具体服务状态。

### 7.7 日志与帮助

| 命令 | 说明 |
|---|---|
| `journalctl -p err -b` | 查看本次启动以来的错误日志 |
| `journalctl -u 服务名` | 查看指定服务日志 |
| `命令 --help` | 查看简要帮助 |
| `man 命令` | 查看手册页 |
| `history` | 查看历史命令 |

在 `man` 或 `less` 中，通常可以用 `/关键词` 搜索，用 `q` 退出。

## 八、常见问题 FAQ

### 8.1 系统与登录

**Q1：忘记登录密码怎么办？**

个人设备可参考对应版本的官方恢复流程；单位统一配发的设备应联系系统管理员。不要直接照搬网络上的管理员密码重置教程，以免违反设备管理要求或影响数据保护机制。

**Q2：需要切换到 root 用户吗？**

日常办公不需要。确需系统管理时，优先使用 `sudo` 执行明确命令，避免长期以最高权限运行桌面和应用。

**Q3：终端在哪里？**

使用 `Ctrl+Alt+T`，或从开始菜单搜索“终端”。部分文件管理器也支持“在终端中打开”。

### 8.2 软件安装

**Q4：提示“无法找到软件包”怎么办？**

先确认包名，再执行 `sudo apt update`。如果仍然找不到，可能是默认仓库未收录、系统版本不支持或处理器架构不匹配。不要随意添加来源不明的软件源。

**Q5：Windows 的 `.exe` 能直接安装吗？**

通常不能。优先寻找 Linux 原生版本、网页版或替代软件。Wine 等兼容方案可运行部分 Windows 程序，但兼容性因软件而异。

**Q6：下载了 deb 包为什么装不上？**

检查系统版本、CPU 架构、软件包完整性和依赖关系。不要把 Ubuntu、Debian、银河麒麟及其他发行版的软件包视为天然通用。

**Q7：安装软件后在哪里找？**

先从开始菜单搜索名称。命令行软件可能没有桌面图标，需要在终端运行。

### 8.3 文件、U 盘与外设

**Q8：U 盘插入后桌面没有显示？**

打开文件管理器查看侧边栏。很多情况下设备已自动挂载，只是没有弹窗。拔出前执行“弹出”或“安全移除”。

**Q9：回收站在哪里？**

UKUI 文件管理器通常提供回收站。命令行 `rm` 删除的文件不一定进入图形界面的回收站，因此不能混为一谈。

**Q10：打印机不能识别怎么办？**

先使用系统打印管理工具添加设备，再检查连接和厂商驱动。不同型号差异较大，应以打印机厂商和系统适配清单为准。

**Q11：蓝牙设备连接了却不能使用？**

先确认设备电量、配对状态和系统识别情况。键盘、音频和 HID 设备的排查路径不同，后续可用单独文章记录具体案例。

### 8.4 网络

**Q12：Wi-Fi 连不上怎么办？**

按顺序检查：密码和信号、无线开关、网络接口、NetworkManager 状态、系统日志。不要一开始就修改大量网络配置。

**Q13：有 IP 地址但打不开网页？**

可能是 DNS、网关、代理或目标服务问题。IP 地址存在只说明本机获得了网络配置，不代表整个链路正常。

**Q14：apt 无法连接软件源？**

检查网络、DNS、代理、软件源地址和系统时间。单位网络还可能存在访问控制，应按管理要求处理。

### 8.5 性能与故障

**Q15：系统很卡，先检查什么？**

```bash
top
free -h
df -h
journalctl -p err -b
```

分别观察进程占用、内存、磁盘和错误日志。不要一上来就删除不认识的系统目录或结束陌生进程。

**Q16：磁盘空间不足怎么办？**

先使用 `df -h` 确认分区，再分析目录占用。下载目录、缓存、旧日志和备份文件都可能是候选，但清理前应确认内容和恢复需求。

**Q17：命令执行后没有任何提示，是成功还是失败？**

很多 Linux 命令成功时不会输出内容。可以查看后续结果，必要时检查退出状态：

```bash
echo $?
```

通常 `0` 表示上一条命令成功，非零表示出现错误，但具体含义仍需结合命令文档。

**Q18：想重装系统怎么办？**

先备份并确认驱动、激活、数据恢复和安全策略。单位统一配发设备建议联系管理员，不要只凭一篇通用教程直接重装。

### 8.6 AI 助手使用

**Q19：AI 给出的命令可以直接执行吗？**

不建议无条件执行。先看命令是否包含删除、覆盖、提权、修改安全策略、下载执行脚本等高风险行为。

**Q20：AI 说已经修复，还需要验证吗？**

需要。验证包括功能恢复、配置持久化、重启后状态，以及是否影响其他应用。

**Q21：可以把日志全部发给 AI 吗？**

日志可能包含用户名、IP、路径、设备标识和业务信息。外发前应脱敏，并遵守所在单位的数据管理要求。

### 8.7 学习心态

**Q22：Linux 是不是很难？**

日常办公与 Windows 有许多相似之处。真正需要适应的是目录、权限和软件管理。可以从图形界面开始，再逐渐学习命令。

**Q23：需要背多少命令？**

不需要一次背完。先掌握 `pwd`、`ls`、`cd`、`cp`、`mv`、`df -h`、`free -h` 等常用查询，再根据实际需求扩展。

**Q24：多久能上手？**

因人而异。与其设定“一周精通”，不如给自己安排几个小目标：会找文件、会装软件、会看磁盘和内存、会保存报错、会验证操作结果。

## 九、给新手的学习建议

### 第一阶段：只用图形界面

先完成日常办公，熟悉开始菜单、文件管理器、系统设置、应用商店和回收站。不要因为别人使用终端，就认为自己也必须马上学习脚本。

### 第二阶段：学会只读查询

掌握 `pwd`、`ls`、`df -h`、`free -h`、`ip addr` 等不会改变系统状态的命令，练习看懂输出。

### 第三阶段：理解修改与回退

在安装软件、修改配置之前，先问三个问题：

1. 这条命令会改什么？
2. 出错后怎样恢复？
3. 完成后怎样验证？

### 第四阶段：用 AI 辅助，而不是放弃判断

让 AI 解释命令、整理日志、提供排查顺序，可以显著提高学习效率。但涉及数据删除、权限、安全策略和业务系统时，仍要保留人工确认。

## 写在最后

从 Windows 迁移到银河麒麟，不需要一开始就掌握复杂的 Linux 知识。先熟悉图形界面，理解家目录和权限边界，再掌握少量查询与安装命令，就足以应对大部分日常办公场景。

国产操作系统的学习和推广，既不需要盲目贬低其他系统，也不必回避兼容性问题。把每一次真实操作、每一个故障和每一种解决方案记录下来，才能逐渐形成可复用的经验。
