# 银河麒麟 V11 桌面老弹「解锁密钥环」？把默认钥匙环改成空密码

> [!tip] 三分钟版
> - **你要的效果**：桌面上的应用访问钥匙环时，不再弹「解锁」对话框，登录后自动可用。
> - **前提**：知道当前默认钥匙环的密码（改了之后是空密码）。忘了也行，但要走重建那条路，代价是已保存的凭据丢失。
> - **最短命令**（改口令，保留已存凭据）：
>   ```bash
>   python3 change_keyring_pw.py      # 脚本见第五节，旧密码只从 stdin 读
>   ```
> - **两条路**：知道旧密码 → 走 D-Bus 私有接口改成空密码（第五节）；忘了旧密码 → 备份后重建（第六节）。
> - **为什么不用图形界面**：seahorse 在麒麟上装不上（依赖冲突），而 gcr-prompter 在 UKUI 桌面下根本弹不出对话框——两条常规路都堵死，才落到 D-Bus 上。
> - **代价**：空密码意味着钥匙环里的凭据以未加密方式保存。这是明确的取舍，请只在自己可控的机器上这么做。

## 一、背景

桌面弹窗「解锁密钥环」，是 gnome-keyring 在钥匙环处于锁定状态、又有应用来取凭据时弹出来的。浏览器要存 Cookie 与表单密码、邮件客户端要存 IMAP 密码、WiFi 要存 PSK，都会走钥匙环。

于是登录系统后，应用一个接一个弹框；不输密码就停在那儿，或者干脆应用起不来。

想根治，通常有三条路：

1. 装图形工具 **seahorse**，右键「登录」钥匙环 → 更改密码；
2. 记住旧密码，用某个工具把密码改成空；
3. 忘掉旧密码，直接把钥匙环删掉重建。

现实是：这条路在银河麒麟 V11 上，前两条分别卡在「装不上」和「弹不出框」，真正能走通的是**直接调 D-Bus 私有接口**。本文就是这次实操的完整记录。

## 二、环境信息

本机实测环境：

| 项目 | 值 |
|---|---|
| 系统 | 银河麒麟 V11 桌面版，ARM64（飞腾） |
| 桌面 | UKUI（非 GNOME，**这是后面弹窗失败的关键**） |
| 密钥环服务 | gnome-keyring，`org.freedesktop.secrets` 在会话总线上 |
| 钥匙环文件 | `~/.local/share/keyrings/默认密钥环.keyring`（**中文文件名**）、`default`（别名）、`user.keystore` |
| 默认钥匙环的 D-Bus 路径 | `/org/freedesktop/secrets/collection/_e9_bb_98_e8_ae_a4_e5_af_86_e9_92_a5_e7_8e_af`（中文名 percent-encode 后的结果） |
| 弹窗组件 | `/usr/libexec/gcr-prompter`（服务文件 `/usr/share/dbus-1/services/org.gnome.keyring.SystemPrompter.service`） |
| Python 绑定 | `python3-dbus` 已装（1.3.2）；`python3-secretstorage` 未装（它会带进 python-secret 全家桶） |
| seahorse | 仓库有候选 3.36-1，但**装不上**（见第七节） |

先记住钥匙环文件在哪，后面所有步骤都围着它转：

```bash
ls -la ~/.local/share/keyrings/
```

## 三、目标与取舍

把默认钥匙环（alias `default`）的口令改成**空**。之后登录系统，钥匙环自动解锁，不再弹框。

三条路线的代价要先讲清楚：

| 路线 | 条件 | 代价 |
|---|---|---|
| 装 seahorse 图形改 | seahorse 能装上 | 本机装不上，且改密码本来也要旧密码 |
| D-Bus 改口令 | 知道旧密码 | 口令为空 = 凭据未加密存储 |
| 删除重建 | 什么都不知道 | **已保存的 WiFi / 浏览器 / 邮件凭据全部丢失** |

## 四、为什么常规两条路都走不通

### 4.1 seahorse 装不上

```bash
sudo apt install -y seahorse
```

结果是依赖冲突：

```text
有一些软件包无法被安装。如果您用的是 unstable 发行版，这也许是因为系统无法达到您要求的状态造成的。
```

查依赖就明白了：

```bash
apt-cache depends seahorse | head -30
dpkg -l | grep -E "gdk-pixbuf|seahorse" | head
```

seahorse 依赖旧命名的 `libgdk-pixbuf2.0`，而 V11 系统里已经是 `libgdk-pixbuf-2.0-0`（t64 命名）。硬装会牵动图形栈——在飞腾平台 + kysec 强校验的环境下，这个风险不值得冒。

**结论：放弃图形工具，直接走 D-Bus。**

### 4.2 gcr-prompter 弹不出对话框

图形改不了，能不能让 gnome-keyring 自己弹框，改成手输？也不行。

先看服务文件，确认弹窗由谁提供：

```bash
cat /usr/share/dbus-1/services/org.gnome.keyring.SystemPrompter.service
# Exec=/usr/libexec/gcr-prompter
```

手动触发一次改口令的 D-Bus 调用：

```bash
dbus-send --session --print-reply --dest=org.freedesktop.secrets \
  /org/freedesktop/secrets/prompt/p1 \
  org.freedesktop.Secret.Prompt.Prompt string:""
```

回的是：

```text
Error org.freedesktop.DBus.Error.NoReply:
Message recipient disconnected from message bus without replying
```

——不是接口不存在，而是**弹窗进程根本没起来**。直接运行它看看：

```bash
DBUS_SESSION_BUS_ADDRESS="$DBUS_SESSION_BUS_ADDRESS" DISPLAY="$DISPLAY" timeout 5 /usr/libexec/gcr-prompter
```

```text
(gcr-prompter:32370): Gdk-WARNING **: Failed to read portal settings:
GDBus.Error:org.freedesktop.DBus.Error.UnknownMethod:
在路径 org.freedesktop.portal.Settings 的对象上没有"/org/freedesktop/portal/desktop"接口
```

进程起来就退。UKUI 桌面没有 xdg-desktop-portal 的 Settings 接口，gcr-prompter 拿不到它需要的环境，直接自杀。

**结论：图形弹窗这条路在 UKUI 上是死的。**（顺带一提：如果你在 GNOME 桌面或带完整 xdg-desktop-portal 的环境下，同样的做法可能直接可用。）

## 五、路线一：D-Bus 直接改口令（保留已存凭据）

### 5.1 原理

seahorse 改密码，走的是 gnome-keyring 的一个**私有**接口，名字很唬人：

```text
org.gnome.keyring.InternalUnsupportedGuiltRiddenInterface
```

名字里带 `Unsupported`，但它是唯一能改口令的入口。方法签名：

```text
ChangeWithMasterPassword(collection_path, old_secret_struct, new_secret_struct)
```

其中 secret 是一个四元组：`(会话对象路径, 参数数组, 口令字节数组, 内容类型)`。

改口令**必须验证旧密码**，这是钥匙环的安全设计，不能绕过——能做的只是把「新密码」留空。

### 5.2 完整脚本

保存为 `change_keyring_pw.py`：

```python
#!/usr/bin/env python3
"""通过 gnome-keyring 私有 D-Bus 接口把默认钥匙环改成空密码。
旧密码只从 stdin 读取，绝不进入命令行 / 环境变量 / 历史。
"""
import getpass
import sys
import dbus

BUS_NAME = "org.freedesktop.secrets"
SERVICE_PATH = "/org/freedesktop/secrets"
ALIAS = "default"

bus = dbus.SessionBus()
service_obj = bus.get_object(BUS_NAME, SERVICE_PATH)
service = dbus.Interface(service_obj, "org.freedesktop.Secret.Service")

collection_path = service.ReadAlias(ALIAS)
if collection_path == "/":
    print("找不到默认钥匙环 (alias=default)", file=sys.stderr)
    sys.exit(1)
print(f"目标钥匙环: {collection_path}")

# 打开一个 plain 加密 session
session_path = service.OpenSession("plain", dbus.String("", variant_level=1))[1]
print(f"Session: {session_path}")

old_pw = getpass.getpass("请输入当前钥匙环密码（不显示）: ")
confirm = getpass.getpass("再次确认要设置为空密码，直接回车确认，输入任何字符取消: ")
if confirm != "":
    print("已取消。")
    sys.exit(2)


def make_secret(pw: str):
    return dbus.Struct(
        (
            dbus.ObjectPath(session_path),
            dbus.Array([], signature="y"),                    # parameters
            dbus.Array([dbus.Byte(b) for b in pw.encode("utf-8")], signature="y"),
            dbus.String("text/plain"),
        ),
        signature="oayays",
    )


guilt = dbus.Interface(
    service_obj,
    "org.gnome.keyring.InternalUnsupportedGuiltRiddenInterface",
)

try:
    guilt.ChangeWithMasterPassword(
        dbus.ObjectPath(collection_path),
        make_secret(old_pw),
        make_secret(""),
    )
except dbus.DBusException as e:
    print(f"修改失败: {e.get_dbus_name()}: {e.get_dbus_message()}", file=sys.stderr)
    sys.exit(3)

print("✅ 已将默认钥匙环密码改为空。下次登录/解锁将自动免输入。")
```

### 5.3 怎么用

```bash
python3 change_keyring_pw.py
```

交互两步：

1. `请输入当前钥匙环密码（不显示）:` —— 输入旧密码，回车（不回显）；
2. `再次确认要设置为空密码，直接回车确认，输入任何字符取消:` —— **直接回车**；输入任何字符则取消。

口令由 `getpass` 从 stdin 读取，**不会进入命令行、环境变量或 shell 历史**——这一点很重要，别改成 `python3 change_keyring_pw.py <你的密码>`。

脚本依赖 `python3-dbus`：

```bash
dpkg -l | grep python3-dbus || sudo apt install -y python3-dbus
```

## 六、路线二：忘了旧密码 —— 备份后重建

改口令要旧密码；完全不知道的话，只能重建，代价是已存凭据丢失。

**第一步，先备份**（这一步不能省）：

```bash
cp -a ~/.local/share/keyrings ~/.local/share/keyrings.bak-$(date +%Y%m%d-%H%M%S)
ls -ld ~/.local/share/keyrings.bak-*
```

**第二步，把旧钥匙环移走**（用移动而不是删除，回退时移回来即可）：

```bash
mv ~/.local/share/keyrings/默认密钥环.keyring \
   ~/.local/share/keyrings/默认密钥环.keyring.old-$(date +%Y%m%d-%H%M%S)
```

**第三步**，下次登录解锁时，会提示创建新的钥匙环，**密码留空**并确认「使用未加密的存储」。

验证是否还弹框：

```bash
dbus-send --session --print-reply --dest=org.freedesktop.secrets \
  /org/freedesktop/secrets org.freedesktop.Secret.Service.ReadAlias string:"default"

COL=$(dbus-send --session --print-reply --dest=org.freedesktop.secrets \
  /org/freedesktop/secrets org.freedesktop.Secret.Service.ReadAlias string:"default" \
  2>/dev/null | grep -oE '"/org/freedesktop/secrets/collection/[^"]*"' | tr -d '"')

dbus-send --session --print-reply --dest=org.freedesktop.secrets "$COL" \
  org.freedesktop.DBus.Properties.Get string:"org.freedesktop.Secret.Collection" string:"Locked"
# variant  boolean false   ← false 表示当前未锁定
```

`Locked=false` 说明钥匙环此刻是解锁状态。

## 七、坑点与排错

### 7.1 seahorse：依赖冲突别硬装

`libgdk-pixbuf2.0`（旧名）与系统的 `libgdk-pixbuf-2.0-0`（t64）冲突。`apt-get install -s` 先模拟一把，看看会动多少东西；涉及图形基础库就别碰了。

### 7.2 gcr-prompter：`Failed to read portal settings` 与立刻退出

这是 UKUI 桌面缺 xdg-desktop-portal Settings 接口导致的，**不是你操作错了**。别在 `gcr-prompter` 上死磕，直接走 D-Bus 私有接口。

### 7.3 `NoReply: Message recipient disconnected`

看到这条别以为是接口名写错了——它只说明**弹窗那一侧的接收方断开了**。先按 4.2 的方法确认 gcr-prompter 能不能起来。

### 7.4 collection 路径是百分号编码的中文名

```text
/org/freedesktop/secrets/collection/_e9_bb_98_e8_ae_a4_e5_af_86_e9_92_a5_e7_8e_af
```

这是「默认密钥环」六个字的 UTF-8 逐字节 percent-encode。**别手写**，用 `ReadAlias("default")` 取，保证跟着实际别名走。

### 7.5 `keyrings` 目录里混进了 GPG 的东西

这台机器上，`~/.local/share/keyrings/` 里除了钥匙环文件，还多出：

```text
pubring.kbx     ← GnuPG 公钥库
trustdb.gpg     ← GnuPG 信任数据库
```

说明有程序把 `~/.local/share/keyrings` 当成了自己的 `GNUPGHOME`。两个世界挤在一个目录里，钥匙环出怪问题时先确认这两者有没有互相干扰。

### 7.6 口令为空 = 凭据不再加密

改完之后，钥匙环里的密码以**未加密方式**保存在磁盘上。共享机器、办公环境要谨慎；自己的笔记本、只存点 WiFi 密码则问题不大。这是你的取舍，不是 bug。

### 7.7 改完不生效？

口令改了但还是弹框，检查是不是改错了对象：`ReadAlias("default")` 指向的才是默认钥匙环。另外注意有些应用缓存了钥匙环句柄，改完建议重登一次。

## 八、命令清单

```bash
# 看钥匙环文件与默认别名
ls -la ~/.local/share/keyrings/
cat ~/.local/share/keyrings/default

# 备份（改之前必做）
cp -a ~/.local/share/keyrings ~/.local/share/keyrings.bak-$(date +%Y%m%d-%H%M%S)

# 确认默认钥匙环的 D-Bus 路径
dbus-send --session --print-reply --dest=org.freedesktop.secrets \
  /org/freedesktop/secrets org.freedesktop.Secret.Service.ReadAlias string:"default"

# 查是否处于锁定状态（false = 未锁定）
COL=$(dbus-send --session --print-reply --dest=org.freedesktop.secrets \
  /org/freedesktop/secrets org.freedesktop.Secret.Service.ReadAlias string:"default" \
  2>/dev/null | grep -oE '"/org/freedesktop/secrets/collection/[^"]*"' | tr -d '"')
dbus-send --session --print-reply --dest=org.freedesktop.secrets "$COL" \
  org.freedesktop.DBus.Properties.Get string:"org.freedesktop.Secret.Collection" string:"Locked"

# 确认弹窗组件在不在、能不能起来
cat /usr/share/dbus-1/services/org.gnome.keyring.SystemPrompter.service
DISPLAY="$DISPLAY" timeout 5 /usr/libexec/gcr-prompter

# 依赖与工具可用性
dpkg -l | grep -E "python3-dbus|seahorse|gcr4"
apt-cache depends seahorse | head -20

# 改口令（脚本见第五节）
python3 change_keyring_pw.py
```

- `默认密钥环.keyring` 现为 3290 字节，2026-11-27 15:04 被改写；7 月 2 日的备份（3124 字节）仍在 `~/.local/share/keyrings.bak-20260702-090041/`；

## 十、总结

这次排障真正的收获不是那句 `ChangeWithMasterPassword`，而是三条判断：

**第一，图形界面不可用时，先确认它为什么不可用。** seahorse 装不上是依赖命名冲突，gcr-prompter 弹不出框是 UKUI 缺 portal 接口——两个都不在你的操作范围内，却各自卡掉一整条常规路径。

**第二，钥匙环的口令改不了，但可以改成空。** 验证旧密码的设计动不了，能动的只有新密码。

**第三，能用 D-Bus 直连服务，就不必依赖它的图形前端。** 组件起不来时，协议层往往还活着——`ReadAlias` 能取到路径，就说明服务是好的。

> **先备份，再改口令；图形走不通，就走协议层；改完验证 `Locked=false`。**
